# Changelog

All notable changes to `@shavin/ui` are recorded here. After 0.1.0, releases are versioned and described with [Changesets](https://github.com/changesets/changesets).

## 0.1.0 — first npm release

The Shavin React primitive library: token-driven components that coding agents can read and check.

### What's in it

- 94 primitives with a documented, machine-readable API (`components.json`)
- The `Container` docs say which size a page uses: `lg` (72rem) for every body section, `xl` for the nav and footer, `full` for media; no change to the component or its default
- Semantic design tokens as CSS variables, a Tailwind 3 preset and Tailwind 4 theme files, light and dark, sRGB and OKLCH builds
- `ThemeProvider` with brand colour, density and scaling, plus a dev inspector that streams live token and contrast checks to the MCP bridge
- The dev inspector loads on demand: a production page that never shows it no longer downloads it
- The dev inspector has a Select tool (one outline that glides between elements, still under reduced motion) and an Issues tool: calm dot and ring markers, a list with filters, and findings for overlapping text, tight line height, contrast on a solid background, horizontal overflow, small tap targets and console errors next to the token checks. Findings are advice and never fail a build. An ignored finding stays in the list in gray and is not counted anywhere. The inspector keeps its own colours, so a page theme cannot restyle it.
- Click an element, a marker or a list row in the dev inspector and one dialog opens beside it (never over the element, the bar or the list; a bottom sheet on a phone): what is wrong and the fix, a note, Ignore, Copy as prompt, and Send to agent. Send reaches an agent through the local bridge (`await_finding`, or `shavin findings` from a shell); the list shows where each finding stands (waiting, with the agent, done, resolved). Ignoring a finding also takes it out of the queue if no agent has it yet.
- The dev inspector is now a control bar that starts as a round tile with the Shavin logo. Drag it by the logo to one of eight spots (it is remembered), collapse it, and use four tools: Select, Issues, Theme and Settings (keys `V`, `I`, `T` and `,`; `Esc` steps back one level; `Alt+Shift+S` hides it). Theme is a floating panel with the same controls the old Theme tab had, plus Copy Theme Code. Settings turns the single-key shortcuts off, reduces motion, reserves room for the bar, forces light or dark controls and clears ignored findings, and has a row that opens the older panel (DS Audit, MCP, Stream). The bar moves out of the way of what you select, panels step around it, and on a phone it is a bottom dock with one shared sheet. The old round launcher, the Theme tab of the older panel and the dashed red outline it drew on violations are removed; the Issues tool replaces the outline. `ShavinDevTools` `position` now sets where the bar starts.
- Server Component helpers in `@shavin/ui/server`
- Accessibility built in: Radix behaviour, visible focus, contrast-checked brand colours
- `PortalContainerProvider` and `usePortalContainer`: a frame that scales or clips its content can make Popover, Menu, ContextMenu, HoverCard, Tooltip, Select and Dropdown open inside it (default is still `document.body`). `BlockPreview` uses it, and its toolbar becomes icon buttons on phones
- `Drawer` takes `trigger`, `defaultOpen` and `onOpenChange` (uncontrolled, no state needed); `open` and `onClose` are now optional. A drawer with no trigger is open by default, as before
- `Table` no longer looks clipped on a narrow screen: when it is wider than its container it fades the edge that still has content, becomes a keyboard-focusable region while it scrolls, and takes `scrollLabel` for the region's name. Do not wrap a `Table` in `overflow-hidden`.
- `Text` docs: `size="overline"` is for a label that adds information, used sparingly; most headings need none (guidance text only, no API change)
- Removed before release: the cross-site URL helpers (`isLocalhost`, `getWebsiteUrl`, `getStudioUrl`, `getDocsUrl`, `getCommunityUrl`, `getKitsUrl`, `getAssetsUrl`) and the `@shavin/ui/lib/docs-routes` subpath (`DOCS_ROUTES`, `docsPath`, `docsUrl`). They only served the Shavin sites; nothing in the published packages links to the documentation website any more. Not breaking for anyone: none of this was in a published release
- The inspector's "Add custom font" option explains how to add a font in place instead of opening the documentation website
- The target size warning (`hitArea="none"`) and the Button, Link and ThemeProvider docs say what the 24px floor is, the trade-off and how to restore it in place; they no longer link to the documentation website
- `ShavinDevTools` no longer reports a made-up "7.1:1 (AAA Pass)" when a colour cannot be read: it says "unknown". Its contrast note names WCAG 2, not 2.1

### Also in this release

Anyone who copied Shavin from the public GitHub repository before this release should read the **Breaking** items.

- **Breaking**: the default display font is Rethink Sans, not Space Grotesk (`--font-display`, the Tailwind preset fallback, the `Monochrome` preset and the Studio, docs and DevTools defaults). Space Grotesk stays in the font list. To keep it, pass `displayFont="Space Grotesk"` to `ThemeProvider`.
- **Breaking**: theme presets are cut from 16 to 9: `Monochrome`, `Midnight`, `Neo Tokyo`, `Terminal`, `Velvet`, `Paper` (was `Minimal`), `Editorial`, `Hearth` (was `Warm`) and `Opal` (was `Nordic`). Removed: `Linear` (use `Midnight`), `Vanguard`, `Cyber`, `Sunset`, `Ocean`, `Oasis` and `Playful`. Brand colour is its own setting, so a removed preset is reproduced with `theme` plus `brandColor`. `Neo Tokyo` now uses Host Grotesk, `Midnight` uses Inter, and `Opal` uses Figtree.
- **Breaking**: the brand colour is `brand`, not `accent`. CSS variables `--accent*` are now `--brand*`, Tailwind colours `accent*` are now `brand*`, and every component class follows (`bg-accent` becomes `bg-brand`). The `ThemeProvider` prop is `brandColor` (was `accentColor`), plus `applyBrandColor`, `BRAND_PRESETS`, the `tone="brand"` / `color="brand"` values, the `shavin-brand` storage key and `tokens.json` `presets.brands`. Why: shadcn/ui owns `--accent`, and the two clashed in one project.
- **Breaking**: `--brand-primary` is removed (and `bg-brand-primary`). Use `--brand` / `bg-brand`.
- **Breaking**: the global stylesheet is split. Element defaults (body type, focus ring, selection, scrollbars) move to `@shavin/ui/base.css` (and `base-oklch.css`); `@shavin/ui/tokens.css` (and `tokens-oklch.css`) hold tokens only. On Tailwind 4, import `base.css` with `layer(base)` after `@import "tailwindcss"`. `styles.css` and `global-oklch.css` still include both.
- **Breaking**: Tailwind 3 CommonJS configs now `require("@shavin/ui/tailwind-preset")` and get a real preset (new `require` export, `dist/tailwind-preset.cjs`). Before, the ES module namespace was returned and no Shavin colour utilities were generated.
- **Breaking**: deprecated APIs are removed: `Dialog` `subtitle` (use `description`), `ActionBar` `onInsert` (use `onAction`), `SegmentedControl` `iconOnly` (use `variant="expand"`), `oklchAchromaticInversion` (use `oklchBrandForMode`) and `MURMUR_FREE_STATES` (use `MURMUR_STATES`).
- `<Icon name>` loads only the icons it renders; the full registry lives in `@shavin/ui/icons` (`preloadIcons`, `ICON_NAMES`, `iconExists`). Server-rendered pages no longer report a hydration mismatch.
- New token `--bg-elevated-hover` (`bg-elevated-hover`): hovered and keyboard-highlighted rows in menus, selects and comboboxes are now visible in dark mode. Visible change: dark-mode highlighted rows are a shade lighter.
- Links and focus rings use the contrast-corrected colour on first paint. `ThemeProvider` defaults to `"system"` and 100% scaling. `TabsTrigger` inherits the `TabsList` variant and orientation.
- **Visible change**: the default focus ring is now thinner and subtler: 1px (was 2px), same 2px offset, same contrast-guaranteed brand text colour. New `focusRing` prop on `ThemeProvider` and `ScopedThemeProvider` (`"subtle"` default, `"default"` = the previous 2px ring, `"strong"` = 3px), backed by new tokens `--focus-width`, `--focus-offset` and `--focus-offset-inset` and a `data-focus-ring` attribute. Opt out of the change with `focusRing="default"`. Every primitive, Studio and the docs follow the tokens (no component draws its own 2px or brand-fill ring any more). Text fields still draw the ring over their border. WCAG 2.4.13 Focus Appearance (AAA) is not claimed for `subtle`.
- Brand-coloured borders, rings and bars that show a state (checked checkbox and radio, selected tab and tab underline, current step, selected day, drop target, selected card) use `brand-text` (`border-brand-text`, `ring-brand-text`, `bg-brand-text`) instead of the raw brand fill, so they reach 3:1 against what they sit next to for any brand colour (lime and other light brands were 1.2-3:1 on light pages). `validate_code` warns on the raw form (`raw-brand-border`).
- Root `styles.css` and `global-oklch.css` for tools that ignore package `exports`. New `WiseOwlLogo` and `WiseOwlMark` sample-brand exports (internal).
- `engines.node` is `>=18.18`.
- **Accessibility claim is WCAG 2.2 AA only (never AAA).** Component docs (`ThemeProvider`, `Heading`, `Text`, `ThemeSwitcher`) and the MCP `synthesize_layout` checklist no longer say AAA; they state what the tests prove: 4.5:1 for text and 3:1 for control boundaries and focus. A unit test fails if a public non-skills source reintroduces an AAA claim. The CLI score badge (build, eval, ledger and test scripts) is now computed from the score and each script's passing threshold (`scripts/lib/grade.mjs`): at or above the threshold it prints VERIFIED with a bronze, silver, gold or platinum tier from a data preset, from the acceptable floor (80) up to the threshold it prints a neutral ACCEPTABLE, and below that NEEDS WORK, instead of a fixed label. Exit codes still use each script's own threshold.
- **Target size policy (WCAG 2.2 AA 2.5.8, never AAA):** every interactive component has a hit area of at least 24×24 CSS px, and under `@media (pointer: coarse)` the primary controls (`Button`, `IconButton`, `TextField`, `Switch`, `Checkbox`, `RadioGroup`, `Tabs`, `SegmentedControl`, `Select`, `SidebarTrigger`, `ThemeSwitcher`, the `CodeBlock` copy and toggle buttons) reach 44×44. The extra area is an invisible `::after` from the new `hit-area` / `hit-area-touch` classes in `base.css`, so size, layout and focus rings are unchanged (use them on custom controls; they need `base.css`, which `styles.css` already includes). **Notable, visible change for touch users:** `TextField`, `Combobox` and the native `Dropdown` grow to a 44px minimum height on touch screens (a native input cannot carry a pseudo-element); desktop is unchanged. One-line opt-out: `<ThemeProvider touchTargets="compact">`, which keeps them at 40 (`md`) and 32 (`sm`) and stops every primary control growing on touch. Also: `Breadcrumbs` links, `Stepper` steps, the `Slider` thumb, `Reasoning`, `Sortable` handles and `FormErrorSummary` links reach 24px; `Resizable` handles are 24px wide for every pointer (were 8px with a mouse); `PanelGroup` dividers hit-test 24px (mouse) and 44px (touch).
- **Target size is switchable and overridable.** `ThemeProvider` and `ScopedThemeProvider` take `touchTargets="comfortable" | "compact"` (default comfortable: today's behaviour; compact: no 44px growth on touch, the 24px WCAG 2.5.8 floor stays). CSS tokens `--tap-min` (24px) and `--tap-min-touch` (44px) tune it. Per component, `hitArea="none" | "default" | "touch"` on `Button`, `IconButton`, `Switch`, `Checkbox`, `RadioGroup` / `Radio`, `Tabs`, `SegmentedControl`, `Select`, `Dropdown`, `Combobox`, `TextField`, `SidebarTrigger`, `ThemeSwitcher`, `CodeBlock`, `Stepper`, `Slider`, `Link`, `Reasoning` and `SortableHandle` (`"none"` can go below 24px; that is yours to own). `hit-area`, `hit-area-touch`, `hit-area-force`, `hit-area-input` and `hit-area-none` are public utilities in `base.css`; they reserve the element's `::after`, and `hitArea="none"` hands it back. `Link` has an opt-in `standalone` prop (24px target for navigation, footer and table-of-contents links; inline links are unchanged). Calendar days, swatches, Rating, Pagination, menu rows, BottomNav and Carousel keep the 24px AA floor; opt in to 44px with `hitArea="touch"` or `hit-area-touch`. Shavin claims WCAG 2.2 AA (2.5.8), not 44px (AAA).
- `hitArea="none"` still works, but in development (`NODE_ENV` not `production`, in the browser) the first use on each component type logs one `console.warn`: it drops the control below the WCAG 2.2 AA 2.5.8 24px floor unless it is already 24px, and the message says how to restore it (remove the prop, `hitArea="default"`, or a 24px target another way). Silent in production and on the server. `ScopedThemeProvider` without `touchTargets` inherits from its parent (documented: it is not an explicit `"comfortable"`; pass one to override a compact page).
- **Visible change:** `Badge` `variant="soft"` for `success`, `warning` and `danger` uses an 8% tint (was 10%), so the text clears 4.5:1 on the blended background in light mode at every gray preset (it was 4.39 to 4.49). The tint is a shade lighter; dark mode and `tone="brand"` are unchanged.
- New state components: `EmptyState` (`kind` first-time / empty / no-results / success), `FormField` (label, hint and error for any control that has none of its own) and `FormErrorSummary` (submit-time error list that takes focus). New exports `concentricRadius` and `paddingScaleFromClassName`; `CalloutProps` is exported.
- `Button` and `IconButton`: new `loading`, `loadingLabel` and `disabledReason` props. **Visible change:** a plain `disabled` button keeps `disabled` but no longer sets `pointer-events: none`, so it shows the not-allowed cursor; `disabledReason` renders `aria-disabled` (focusable) with the reason in a Tooltip; `loading` keeps the button focusable with the progress cursor. Hover and press styles are off in all three states.
- **Visible change (brand text contrast):** `--brand-contrast`, `--brand-text`, `--link` and `--focus` (`brandTextFor`, `oklchTextFor`, and the CLI `shavin brand` output) now guarantee 4.5:1 for brand-coloured text for any brand colour, light and dark, on every page fill of every gray preset (including dark `elevated-hover`) and on the brand's own soft tint over them (Badge `soft`, Button and IconButton `soft` and their hover, Avatar `soft`). Before, only the plain page fills were checked, so `Badge tone="brand" variant="soft"` could fall to 4.19:1 (light) and 4.23:1 (dark). Links, underlines and focus rings use the same colour, so they clear 3:1 (WCAG 1.4.11) as well. Hue is kept; only lightness moves. Notable for brands whose text colour shifts: of the 24 presets, 41 of 48 preset x mode text colours change, by a median OKLCH lightness of 0.06 (largest 0.10, for example Blue dark text goes from rgb(0 144 255) to rgb(77 177 255), Tomato light from rgb(192 65 39) to rgb(169 57 34)). Unchanged: Monochrome, Lime (both modes), and Mint, Sky and Amber in dark mode. Barely visible (at most 5 of 255 per channel): Mint, Sky and Amber in light mode. A brand that already passes everywhere (a deep navy in light mode) keeps its text colour. Dark-mode brand text is lighter, and light-mode brand text darker, than before. Solid fills (`bg-brand`) are untouched. The visible colour change was reviewed against a before/after preview.
- `Link` is a stand-alone link (24px hit area, no layout change) by default when `underline="none"`, because agents write every navigation and footer link that way and left out `standalone`; `standalone={false}` opts out. Links with an underline are unchanged.
- **Visible change:** `StatCard alert` no longer underlines the value (an underline reads as a link). It shows a warning dot before the label and "Needs attention" for screen readers.
- The dev inspector's MCP tool list shows the new `render_check` tool (one line in `ShavinDevTools`).
- **Visible change (brand text, raw `text-brand` removed):** 27 class lists in 12 primitives used `text-brand` (the brand FILL) as a text or icon colour, which fails contrast for light brands such as lime or yellow and for dark brands in dark mode. They now use `text-brand-text` (the contrast-guaranteed colour): Pagination cards hover, Rating `tone="brand"`, Toast info icon, Stepper current step, SegmentedControl on-state, BottomNav active item, Select checked item, AlertDialog info, IconPicker selected, TimePicker active mode, BlockPreview prompt and the dev inspector. Brand text in those components shifts to the same colour as links and `Text color="brand"`. Use `text-brand-text` (or `text-brand-contrast`) in your own code; `text-brand-fg` is for text on a solid `bg-brand`. `validate_code` warns on raw `text-brand` (`raw-brand-text`).
- **Notable (Studio exported files, brand text):** Studio code export now writes `text-brand-text` for text with `color="brand"` instead of the raw `text-brand` fill, so exported brand text keeps its contrast on light and dark brands. Studio still reads `text-brand`, `text-brand-text` and `text-brand-contrast` as the brand colour, so older files open unchanged. The first time you save or export an older file, its brand text classes are rewritten to `text-brand-text`: a one-time change in the diff, same colour on the canvas. The `autofix` helper in the evals maps colour utilities to `text-brand-text` too.
- **Visible change (solid brand fills, `brandSolid`):** solid brand buttons, badges and selected states used the exact brand fill, so most presets got near-black text on a mid-tone fill (14 of the 24 presets, in light and dark). New tokens `--brand-solid` and `--brand-solid-hover` (`bg-brand-solid`, `hover:bg-brand-solid-hover`, `border-brand-solid`, plus `--brand-on-dark-*` and `--brand-on-light-*` twins) hold the fill under text, and `--brand-fg` is the text on them. The default, `ThemeProvider` `brandSolid="accessible"`, keeps the brand's hue and lowers OKLCH lightness just far enough for **white text at 4.6:1**: 14 of 24 presets get a slightly deeper fill (Tomato, Red, Ruby, Crimson, Pink, Blue, Cyan, Teal, Jade, Green, Grass, Gold, Bronze, Brown; lightness drop median 0.067, largest 0.107 on Cyan), the hover fill keeps the text at 4.5:1, and a genuinely light brand (Lime, Mint, Sky, Amber, and Monochrome in dark mode) keeps its exact fill with dark text. `--brand` itself does not change. Opt out with `brandSolid="exact"` (the previous output, byte for byte); `brandSolid="perceptual"` keeps the exact fill and picks white text wherever APCA prefers it, which misses WCAG 2 AA on 14 of 24 presets and logs a one-time development warning. `ScopedThemeProvider` takes the same prop and inherits the provider's. Every primitive that puts text on the brand (Button, IconButton, Badge, Avatar, Tabs, SegmentedControl, Stepper, Pagination, Calendar, TimePicker, DatePicker, BottomNav, ChatBubble, AlertDialog, SentimentRating) and the on-state of Switch, Checkbox, RadioGroup, Slider and Progress use it; `Button` and `IconButton` hover with `hover:bg-brand-solid-hover` instead of `hover:opacity-90`. In your own code use `bg-brand-solid text-brand-fg hover:bg-brand-solid-hover` for anything with text on the brand and keep `bg-brand` for decoration; `validate_code` warns on `bg-brand` with `text-brand-fg` (`raw-brand-solid`). Overriding `--brand-solid` or `--brand-fg` in your own CSS bypasses the guarantee. The shadcn bridge maps `--primary` to `--brand-solid`. CLI: `shavin brand` adds `--brand-<name>-solid`, `-solid-hover` and a matching `-fg` for every extra brand colour (`--brand-solid-mode: accessible | exact | perceptual;` in `brand-tokens.css`; `solid`, `solid-hover` and `solid-mode` are now reserved names), and `shavin doctor` / `inspect_environment` report the active mode, flag `perceptual` and warn on literal overrides under 4.5:1. Studio exports `brandSolid` on the ThemeProvider it generates.
- **Visible change (readable text over background media):** a layout (`Section`, `Box`, `Container`, `Flex`, `Grid`, `Card`) with a photo (`bgImage`), video (`bgVideo`) or `fx:` backdrop and no `surface` now defaults to `surface="dark-always"` (light text) and adds a scrim unless the overlays already have one: `dark-30` for photos and video, `dark-50` for fx. Before, the text kept the page colour and was often unreadable. An explicit `surface` or overlay always wins, a `light-*` tint keeps dark text, and meshes and custom gradients are unchanged because their tone depends on the page theme (set `surface` yourself). New export `resolveBgReadability`.
- **Visible change:** `Callout` sets `role="alert"` for `color="danger"` and `role="status"` for the other colours; pass `role="note"` for a static notice.
- `TextField` error messages show an icon and are announced once when they appear (`announceError`, default true). `DatePicker` and `TimePicker` accept `aria-invalid` / `aria-required` (and `TimePicker` `id`, `aria-labelledby`, `aria-describedby`). `Tooltip` accepts controlled `open` / `onOpenChange`.
- **Visible change:** `Toast` shows at most three toasts at once, drops an identical message that is already showing, keeps plain errors for 8 seconds, and below the md breakpoint moves the stack to the bottom centre at full width.
- **Breaking**: `concentricCompoundStyle` is removed. Its value referenced `--radius-panel-inner` inside itself, a CSS cycle that resolved to nothing. Nest a padded `Card` instead (nested Cards are now concentric).
- **Visible change (radius):** translucent `Box` / `Flex` / `Grid` / `Section` take the inner radius from their real padding (className) instead of assuming `p-4`; `Card padding="none"` gives flush children its own radius instead of an ancestor's; a `Card` inside a `Card` uses the parent's inner radius; menu, select, dropdown and context-menu items are inset by `p-1` and use `rounded-panel-p1`; segmented `Tabs` use `rounded-panel-p1`; `SegmentedControl` uses the new `rounded-control-inner` utility; `Stepper`, `IconPicker` and `ContextMenu` no longer use the undefined `--radius-md` (it rendered square). `applyRadiusPreset` and `themeCss` also set `--radius-panel-inner`.
- **Breaking (build output)**: the package ships one ES module per source file with explicit `.js` imports and `sideEffects` set, instead of one flattened `dist/index.js`, so bundlers drop the components a page does not import. In a production Next 15 build a Button-only page drops from about 245 kB to about 28 kB gzip over an empty page; Vite and esbuild with code splitting show the same cut. Bundled `.d.ts` files stay per public entry. The package is ESM only (the Tailwind 3 preset still ships as CommonJS). The motion runtime no longer boots as a side effect of importing the root (that would keep the whole library in every bundle): `ThemeProvider` starts it on mount, and an app without a ThemeProvider calls `initMotionRuntime()`.
- **Fix**: `ThemeProvider` follows the OS appearance in client-only apps (Vite, `createRoot`). The inline `ThemeScript` only runs in server-rendered HTML, so such an app stayed light on a dark OS. On mount, before first paint, `ThemeProvider` now sets the `dark` class, `data-theme` and `color-scheme` from the stored choice or the OS setting, applies the brand tokens for that appearance and, while the preference is "system", follows OS changes. A stored light or dark choice (or `defaultTheme`) is respected, and HTML that was already resolved (server-rendered apps, next-themes) is left alone. A page that shows content before the bundle runs can still flash light for one frame; put the same appearance script in `index.html` to avoid it.
- **Breaking**: the package no longer includes its `src` folder, and the `@shavin/ui/primitives/*` and `@shavin/ui/lib/*` subpaths (raw TypeScript) are removed. Import everything from `@shavin/ui` (`cn` and the theme preset functions are exported from the root; `cn` is also in `@shavin/ui/server`). The one kept subpath is `@shavin/ui/lib/theme-presets` (compiled, with types). `@shavin/ui/styles/*` and the brand files now resolve to `dist/styles`. `OVERLAY_PRESET_STYLES` is exported from the root.
- `<Icon name>` loads its name tables with the first named icon instead of with the bundle. `motionConfig.loadGsap` lets you supply GSAP yourself (the default loader sits in its own module); with esbuild without code splitting, mark `gsap` external, set `motionConfig.gsap = false` or supply the loader.
